Runspindle / Browser design

Access with boundaries.
Control with an owner.

Browser is intended to make an authorized account available to a bounded task while keeping credentials, human input and agent input under separate controls. A managed session can preserve continuity; it cannot create permission.

Design, not a running service. This page is a newly authored static explanation. Local synthetic and protocol checks exist in the repository. Real authority adapters, trusted browser observations, distributed fencing, provider integration, encrypted profiles and live acceptance are not established. No production deployment or measured outcomes are claimed.

Architecture System map Control flow Evidence and gaps

Three requirements, one account boundary

  • Preserve browser identity

    The intended agent API and authorized human view must reach the same headed browser, account and native session on the explicitly selected host. Neither a reused process identifier nor a matching page title proves this binding. Account profiles must remain isolated.

  • Fence before transferring control

    Only one controller may supply input. A broker must reject stale lease epochs, drain or cancel queued commands and revoke interactive streams before a new controller is admitted. Passive viewing is separately authorized read-only access, not takeover.

  • Keep uncertainty durable

    Durable orchestration records intent, waits and recovery. It cannot prove whether a website accepted a submission. Persist an uncertain effect before dispatch; reconcile observations before retrying, including after restart.

Proposed integration roles

These are boundaries to integrate and qualify, not a deployed stack. A named product's capabilities do not establish Runspindle's end-to-end behavior.

  • PinchTab: bounded browser actions

    Browser would use an adapter for tab actions, snapshots and attachment to the selected browser. That API must not be treated as account-scoped authority. Core grants, Host identity and Browser lease checks must constrain each command. Native adapter conformance remains blocked.

  • KasmVNC: a view of the same browser

    The proposed visual surface must observe the browser used by the action API. Passive view and interactive input require different capabilities. Gateway revocation must terminate existing input and streams at control changes; that live behavior is unverified.

  • OpenBao: references before values

    A local KV-v2 protocol adapter exists with process-local opaque handles and synthetic transport tests. Production workload identity, provider integration and Transit envelope encryption remain planned. Trusted helpers, not the model or page, must resolve references for an approved principal, account, origin, operation and current lease.

  • Temporal: durable coordination

    Core would coordinate workflow state, approval waits and bounded retry policy through Temporal. Browser-side fencing and target-site reconciliation remain separate obligations; a successful orchestration step is not proof of an external effect.

  • Authelia and Pomerium: distinct identity roles

    An identity provider for OIDC/MFA and an identity-aware route proxy are proposed complementary roles. Named interoperability is untested. A proxy session must not imply an approved website action or possession of that site's account.

  • Caddy: optional ingress

    An outer TLS and general ingress adapter may be appropriate for a chosen host. It is not a second source of action authority or a required duplicate authentication chain. No ingress installation or activation is supplied by this document.

Read the system map without an interactive island

Every role is visible from the start. The numbered reading order is a guide to responsibilities, not a network topology, execution trace or claim that credentials pass through every component. No animation, hover, scroll threshold or JavaScript is needed to reveal information.

Transfer control in explicit stages

  1. Establish the request

    Verify the principal, selected account, approved action and target through trusted identity and observations. Model output, page text and received feedback cannot enlarge the grant.

  2. Bind the session

    Acquire the current account lease on the explicitly pinned host and restore only an authorized isolated profile. A saved profile is neither a shared credential nor proof that a website session remains valid.

  3. Dispatch within the grant

    Route bounded commands through the broker, rechecking account, origin and epoch at use. If cancellation, redirect or a lease change intervenes, deny the action and clean up. Preserve uncertain external outcomes instead of blindly retrying.

  4. Fence, then transfer

    Stop old input, close interactive streams and authenticate the next controller before granting a fresh epoch. Resume only after authenticated human release, viewer input closure and fresh account/target observations. Restart, timeout or disconnect must not silently restore agent control.

Forgetting a credential, deleting an encrypted profile and revoking a website session are distinct operations. Human intervention is an execution event, not automatic consent to export a training example. Repetition does not create recurring authorization.

Evidence that exists, gaps that remain

  • Local component evidence

    The repository documents synthetic vault fixtures, a local durable effect journal, default-deny resolver orchestration, and an OpenBao protocol adapter. These bounded tests do not establish production authority, real provider behavior or live browser control.

  • Runtime acceptance still required

    Trusted origin and account observations, authenticated authority adapters, distributed lease enforcement, same-browser proof, live stream revocation, profile encryption and identity/provider integration remain unqualified. No source repository's historical test result transfers to Runspindle.

  • Document checks only

    This dependency-free HTML has source-level checks for local links, section accounting, dependency exclusions and evidence boundaries. Actual desktop/mobile rendering and keyboard behavior have not been verified. The composition repository mirror remains pending. Issue #5 stays open until those acceptance checks and independent review are complete.

  • No release authority implied

    Keep synthetic tests, isolated integration, bounded live acceptance and production deployment separate. Production needs independent secrets, routing, rollback, monitoring and operator evidence. Passing document checks neither activates services nor grants permission to publish, deploy or use an account.
